我们的投研团队每天要给几十只固定利率债券估值，人工用表格拉现金流既慢又容易在贴现指数上出错，希望有一个能长期跑在内网、只通过 HTTP 提供服务的债券估值与利率风险核算引擎，把定价口径固化下来，供上游报价系统与风控系统直接调用。

核算对象是标准的固定利率附息债：给定面值、票息年利率、每年付息频率、剩余到期年数以及市场年化到期收益率，服务要算出债券全价、每一期现金流的现值明细、麦考利久期、修正久期与凸性。计价口径要统一并固定下来：把年化收益率按付息频率折算成每期折现率，末期同时支付最后一期票息与面值，全价等于各期现金流按对应期数贴现后的求和；麦考利久期是各期「时间（以年计）乘以该期现值」的加权和再除以全价；修正久期等于麦考利久期除以「一加每期折现率」；凸性按各期「期数带来的二阶权重乘现值」求和后除以全价并除以「一加每期折现率」的平方，这套惯例一旦选定就要在定价、久期、凸性三处保持一致，不能一处按年、另一处按付息期。

服务还要能做一阶与二阶的价格敏感度估计：给定一个收益率变动量，用修正久期给出一阶价格变化近似，再叠加凸性项得到二阶近似；当收益率上行时，含凸性修正的二阶估计应当比只用久期的一阶估计更贴近重新按新收益率精确定价的结果，也就是价格跌得更少，这条关系要能通过服务自身重算得到印证，而不是写死的结论。

有几条内在关系必须始终成立，请把它们作为正确性的基准并用测试锁住：平价债券（票息率等于到期收益率）的全价应当等于面值；零息债（票息为零）的麦考利久期应当恰好等于剩余到期年数；在其它条件不变、仅抬高到期收益率时，全价下降；把付息频率成倍加密而保持年化票息与年化收益率不变时，现金流分布随之变密，全价必须用同一收益率重新贴现后仍与久期、凸性口径自洽。输入校验要在计算前完成：面值非正、到期年数非正、票息率为负、或到期收益率低到使某期折现因子非正等非法组合，一律返回带有清晰错误说明的结构化错误响应，而不是抛出未处理异常或返回残缺数字。

对外接口以 JSON 交互，至少覆盖：一个只做定价、返回全价与逐期现值明细的入口；一个返回麦考利久期、修正久期与凸性的入口；一个接收收益率变动量、返回一阶近似、二阶近似与精确重定价三者对照的入口。服务需要能同时处理多个并发请求，各请求之间的中间计算互不干扰、互不覆盖。为方便验证，随服务内置一份可手工核对的示范债券参数（例如一只五年期平价债），使用者加载它即可复现上面的平价与久期关系。

技术选型上，后端语言选 Python 3.12，Web 框架用 FastAPI。工程结构要有清晰的职责边界：现金流梯子的构建、贴现与全价计算、久期与凸性、敏感度估计、输入校验、以及对外的 HTTP 接口，分别落在各自的模块与文件里，避免所有逻辑挤在一处。测试方面，请覆盖平价债全价等于面值、零息久期等于到期、收益率上行价格下降、付息频率加密后的口径自洽，以及各类非法输入被拒这几组行为。交付形态是容器化服务，本地用单条命令即可完成镜像构建并把服务拉起、监听 HTTP 端口，运行时基础镜像固定为 Python 3.12。整个服务只负责上述债券估值与利率风险计算这一件事，只经 HTTP 暴露，不带任何页面，也不涉及账户、持仓或成交流水。
